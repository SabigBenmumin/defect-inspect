# Introduction
ระบบนี้ทำมาเพื่อทำการตรวจจับความผิดปกติ หรือการตรวจจับชิ้นงานที่มีตำหนิหรือเสียหาย
สิ่งที่เราสนใจคือตำหนิ\
ซึ่งหมายความว่าเมื่อโมเดลมีผลทำนายว่าเป็น **positive**(predicted positive) นั้นหมายถึงเจอตำหนิ (defect) และผลที่ได้ก็คือตัดสินใจ **reject**\
ส่วน **predicted negative** หมายถึงโมเดลไม่เจอตำหนิ และผลที่ได้ก็คือตัดสินใจ **accept**

# Positive Class
Positive Class: คือ defective data/anomaly data (actual) หรือสิ่งที่เราต้องการตรวจพบ

# หน่วยการตัดสินใจ
ไม่แน่ใจว่า 1 ภาพเท่ากับหนึ่งชิ้นหรือเปล่าแต่คิดว่า 1 ภาพไม่เกินหนึ่งชิ้น
จากที่ไปดูในรูปมาคือจะเห็นว่าเป็นภาพที่ส่องไปที่ชิ้นงาน

สามารถสมมุติฐานได้ดังนี้คือ **assumption**
1. ความเป็นไปได้ว่าหนึ่งชิ้นอาจมีหนึ่งภาพหรือมากกว่า จากการที่ภาพที่เห็นเป็นการนำกล้องไปส่องที่ชิ้นงานซึ่งไม่ได้เห็นเต็มชิ้น
2. ความเป็นไปได้ที่หนึ่งชิ้นต่อหนึ่งภาพ ในกรณีที่การตรวจจะเป็นการตรวจเฉพาะจุดโดยกำหนดและจัดวาง aligment ของวัตถุกับกล้องมาแบบตายตัวที่จุดเดียว
การประเมิน **assumption** จากสมุติฐานข้างต้น
- ถ้าเป็นไปตาม **assumption 1** และหน่วยการตัดสินใจเป็นต่อหนึ่งชิ้น ถ้าการทดสอบ **FA** และ **FR** โดยเฉพาะ **FA** (ที่ต่อให้คิด 1img/piece ยังไม่ผ่าน Req-1 เลย) จะยากขึ้นมากเนื่องจากอาจมีชิ้นที่มีหลายภาพและเมื่อหน่วยคือชิ้นก็จะทำให้ข้อมูลในการตัดสินใจลดน้อยลง และทำให้ **FA** ลดลงและ **FR** ต่อชิ้นสูงขึ้นเมื่อเทียบกับ 1img/piece เพราะยิ่งมีข้อมูลให้จับผิดเยอะขึ้น และอีกความยุ่งยากนึงคือใน dataset ไม่มี metadata ระบุว่าภาพไหนมาจากชิ้นไหนบ้าง แต่ถ้าต้องการให้หน่วยการตัดสินใจยังเป็นต่อภาพก็ไม่ได้มีปัญหาอะไรเนื่องจากไม่ว่าชิ้นงานจะเจอตำหนิกี่ภาพเมื่อโมเดลระบุว่าจะ reject ภาพใดภาพหนึ่งแค่หนึ่งภาพของชิ้นงานนั้น เราก็แค่ reject ชิ้นงานนั้น

Assumption: ประเมินบน KSDD2 โดยนับ 1 ภาพ = 1 ชิ้น (dataset ไม่มี piece ID จึงทำแบบอื่นไม่ได้)

แต่จากการที่ต้องนำผลจาก **model** มาทำการ **reject** / **accept** ดังนั้นหน่วยที่ต้องมีคือชิ้น เนื่องจากไม่แน่จะว่าภาพและชิ้นเป็น 1:1 หรือไม่ แต่ไม่ว่าจะเป็น 1 ภาพต่อหนึ่งชิ้นหรือหลายภาพต่อหนึ่งชิ้นเมื่อเมื่อเจอ **defect** แล้วยังไงก็ต้อง **reject** ชิ้นนั้นเลย

ในกรณีที่เป็น **segmentation model** เราต้องมี threshold ว่าความเสียหายมีพื้นที่ในรูปเท่าไหร่ถึงจะจัดว่ามี defect หรืออาจจะใช้แบบ PaDiM/PatchCore

# definition of FR/FA
**False reject** คือการที่ model ทำงานผิดพลาดโดยการมองชิ้นงานที่ดีเป็นของเสียและทำการ reject\
**False accept** คือการที่ model ทำงานผิดพลาดโดยการมองชิ้นที่มีตำหนิเป็นชิ้นงานดี แล้วทำการ accept

# Threshold policy
เลือกล๊อค **FA** ก่อน แล้วค่อยทำการ optimize  **FR** บน **validation set**\
**test set** ใช้ได้แค่ 1 ครั้งตอนที่ทำการทดสอบโมเดลหลังจาก **train** เสร็จแล้วเท่านั้นเพื่อป้องกันไม่ให้เกิด **optimistic bias**


ถ้าไม่มี **threshold** ไหนผ่านทั้งสองข้อ \
แสดงว่าปัญหาอาจไม่ได้อยู่ที่ **threshold** ทำการพิจารณากระบวนการต่อไปนี้
- ปรับ เพิ่ม/ลด training data
- ลองวิเคราะห์ score ของชิ้นงานดีและมีตำหนิ ดูว่า overlap กันมั้ย ถ้า overlap กันเยอะแสดงว่าตัวโมเดลเองยังแยกแยะได้ไม่ดี -> ปรับ model/feature หรืออาจะเปลี่ยน model
- ลองดูว่าสามารถทำ **image preprocessing** วิธีไหนได้บ้างมั้ย
 
ในกรณีที่ val มีภาพเสียน้อย จนหลุดแค่ 1 ภาพทำให้ **FA** โดดเกิน 0.5%
- พิจารณาการปรับสัดส่วน data set ใหม่อาจจะแบ่ง train set ให้ validation set


# test set ยืนยันอะไรได้
**a**. ถ้าโมเดลไม่พลาดการ **reject** ของเสียเลยใน **test** (0 จาก 110 รูป) ที่ความมั่นใจ 95% จะได้ **FA rate** = $\frac{3}{110} <= 2.73\%$ จึงยังไม่สามารถยืนยัน **Req-1** ได้\

**b**. ที่มาของสูตรใน a. คือ
เมื่อ confidence interval = 95% ดังนั้นโอกาสที่จะไม่เกิดเหตุการณ์ตามที่เรามั่นใจเหลือน้อยกว่าหรือเท่ากับ 5% หรือ 0.05
from $P(\text{0 escape}) = (1-p)^n$ =แทนค่าและ take ln=> $n \cdot \ln(1-p)=\ln(0.05) \approx -3.00$\
=> $\ln(1-p) \approx -p$\
=> $n \cdot (-p) \approx -3.00$ => $-p \approx \frac{-3.00}{n}$

**c**. เนื่องจาก **sample size** ของ **defected-free sample** (test) มีขนาดใหญ่ทำให้ **FR rate** ยืนยันได้ง่ายกว่า

**d** จากข้อมูลชุดนี้ ถ้า test แล้วไม่มี **FR** หรือ ทำการ reject 0 จาก 894 ถาพ(defected free-actual) เราสามารถยืนยันได้ว่าโมเดลของเราจะ **accept** ชิ้นงานดีได้อย่างแม่นยำตาม **Req-2** ต่อให้ reject ชิ้นดีผิดไปถึง 33 ภาพ (FR ที่วัดได้ ≈ 3.7%) ขอบบน 95% ก็ยังอยู่ที่ 4.9% ซึ่งไม่เกิน 5% ตาม **Req-2**\
แต่ถ้าไม่ผ่านก็ต้องพิจารณาจำนวนที่เราจะเผื่อให้พลาดได้มาคำนวนว่าต้องเพิ่มเท่าไหร่เพื่อเพิ่มขนาด **sample size**\
แต่เนื่องจาก **defected data** ใน **test** มี **sample size** ที่ค่อนข้างเล็กทำให้ในทางสถิติเราสามารถบอกได้ว่าเสี่ยงที่จะเกิด **FA** (ปล่อยของเสียหลุดรอด) ได้แย่สุดถึง 2.73% แม้จะไม่มี **FA** เลยก็ตาม(พลาด 0/110) ซึ่งก็ยังไม่ผ่าน **Req-1**

# Data requirement
**a**. ต้องมีภาพเสียใน **test set** ที่อย่างน้อย 600, ได้จากการคำนวนย้อนกลับ 3/n=0.005 => n=3/0.005=600

**b**. ถ้าใน production line ผลิตชิ้นงานเสีย 1% ต้องเปิดไลน์ผลิต 60,000(600/0.01) ชิ้นเพื่อให้ได้ defected data 600 ชิ้น, \

**c**. แนวทางเพิ่มข้อมูลของเสีย
1. ยืดเวลาทดสอบออก แล้วเพิ่มเวลาการเก็บข้อมูลจากไลน์ผลิต + นำข้อมูลจากสายการผลิตเก่า
   1. ต้องยืดเวลา **deliver** งานออกทำให้กินเวลานานขึ้นกว่าจะทำเสร็จและใช้งานจริง 
   2. การดึงจากสายการผลิตเก่าอาจทำให้สถาพแวดล้อมในการบันทึกรูปคาดเคลื่อนหรือแตกต่างทำให้ความเป็นตัวแทนของไลน์จริงลดลง
2. จำลองรอยขีดหรือตำหนิ โดยจำลองอย่างเคร่งขัด ผ่านการวิเคราะห์สาเหตุของการเกิดตำหนิและจำลองสถานการณ์เพื่อให้เกิดตำหนิบนชิ้นงานแล้วเก็บ data, ความเป็นตัวแทนของข้อมูลในสายการผลิตจริงขึ้นอยู่กับความใกล้เคียงของสภาพแวดล้อม setup และเหตุการณ์ที่เกิดตำหนิบนชิ้นงาน

**d**. metadata
- **รูป** เช่น image shape(size),image reslution เพื่อให้ง่ายต่อการความคุมและคำนึงถึงผลกระทบของ model ที่เกิดจาก input
- **setup ของกล้อง** เช่น lence, distance(camera/lence ถึงชิ้นงาน) เนื่องจากส่งผลต่อความบิดของรูปและรายละเอียดในรูป
- **basic metadata** เช่น วันที่ถ่าย, สายการผลิต id,lot/batch number (ล๊อตการผลิตสินค้า) สำหรับการตรวจสอบย้อนหลังว่า data นี้มาจากไหน เมื่อไหร่
